# Internal Developer AI Usage vs. Engineering Output: Findings & Empirical Analysis

## 1. Executive Summary

**The Core Question:** When internal software engineers and employees consume AI tokens, how does that translate into measurable output and workforce productivity?

**The Core Finding:** Internal AI usage has moved from simple autocomplete (2024) to full-scale system modernization (2025) and autonomous multi-agent pull request generation (2026). Across disclosing tech leaders:
*   **Google:** AI-generated code share surged from **25% (late 2024)** to **50% (2025)** and **~75% (2026)** via internal tool "Goose".
*   **Microsoft:** Empirical study of **16,000+ engineers** showed **+40.5% more completed pull requests** and **55% faster task completion**.
*   **Amazon:** Amazon Q Developer saved **4,500 developer-years** of work, cutting production application upgrades from **50 days down to hours** (79% of AI code accepted as-is).
*   **Stripe:** Internal "Minions" multi-agent system autonomously authors, tests, and lands **~1,300 pull requests per week**.
*   **Meta:** Targeting **50% to 75% of internal code** written by AI agents; autonomous bug-fixing agents running across monorepo.
*   **Klarna:** Automated the workload of **700–853 full-time equivalent agents**, reducing resolution time from 11 minutes to under 2 minutes.

## 3. Four Key Structural Discoveries

1.  **The Bottleneck Inversion:** AI makes drafting code nearly free and instantaneous. The new bottleneck in software engineering is **code review, integration testing, and architectural validation**.
2.  **The Modernization Dividend (Amazon Q):** The highest ROI on internal AI tokens is not writing greenfield code—it is **refactoring and modernizing legacy codebases** (e.g., upgrading Java, migrating frameworks), where deterministic tests provide instant ground truth.
3.  **The Autonomous Multi-Agent Leap (Stripe Minions):** Moving from passive autocomplete in an IDE to asynchronous background agents triggered via Slack reactions multiplies output without requiring developers to babysit the generation process.
4.  **The Experience Equalizer:** Less experienced developers experience the largest productivity multiplier (+50% to +80%), democratizing high-velocity engineering across junior and mid-level tiers.
